Política de Privacidade — Mixlirous

Última atualização: ciclo QA inicial (2026-09). Esta página é um resumo estático da política viva servida pela API em /api/v1/system/privacy-policy (autenticada); em caso de divergência, a API é a fonte da verdade.

Encarregado pelo tratamento de dados pessoais (DPO): dpo@mixlirous.local — substitua pelo canal oficial do domínio onde esta instalação está publicada.

1. Quem é o controlador

Esta instalação do Mixlirous é operada pelo time responsável pelo domínio onde a aplicação está publicada. O responsável pelo tratamento (DPO) pode ser contactado pelo canal de segurança divulgado no /.well-known/security.txt quando configurado.

2. Dados pessoais tratados

O Mixlirous processa áudio enviado pelo titular (faixas, stems, uploads), metadados de produção (configurações de mix, parâmetros de efeitos) e credenciais de sessão (JWT, cookie mixlirous_session para SSE same-origin). O provedor LLM ativo recebe apenas metadados numéricos e prompts — o áudio original nunca é enviado para o provedor externo.

3. Finalidade e base legal

Tratamento necessário para a execução de contrato (Art. 7º, V LGPD): o titular envia áudio e parâmetros para receber uma mixagem processada. A análise assistida por IA usa apenas metadados derivados (BPM, tonalidade, energia), não o áudio em si.

4. Compartilhamento com terceiros

Para instalações com provedor LLM externo (ex.: OpenAI, Anthropic), prompts e metadados de análise são enviados ao provedor. O provedor é identificado em /api/v1/system/info e a política de retenção dele se aplica em adição a esta. Para instalações com Ollama local, todo o processamento é on-premise — sem egress de áudio ou prompts.

5. Retenção

O áudio enviado e os artefatos gerados ficam no storage desta instalação (disco local, MinIO ou S3) até o tenant excluí-los; não há expiração automática configurável nesta versão. O titular pode excluir faixas e jobs a qualquer momento pela UI; a revogação do consentimento (LGPD Art. 8º) remove o registro ativo.

6. Treinamento de modelos

Nesta instalação não existe pipeline de treinamento: áudio e prompts não são usados para treinar modelos. Com provedor externo, verifique também a política de retenção/treino do próprio provedor.

7. Direitos do titular (LGPD Art. 18)

O titular pode solicitar: confirmação de tratamento, acesso aos dados, correção, anonimização, portabilidade, eliminação. Solicitações devem ser feitas pelo canal de segurança divulgado em /.well-known/security.txt.

8. Segurança

Tráfego sobre HTTPS com HSTS (Strict-Transport-Security: max-age=63072000). Cookies de sessão HttpOnly + SameSite=Lax. JWT assinado com segredo configurado por ambiente (falha o boot em CONFIG_ENV não-local sem JWT_SECRET).

9. Mudanças nesta política

Esta página é estática; a política viva é servida pela API e pode divergir conforme o provedor LLM ativo. Sempre confira /api/v1/system/privacy-policy para o estado atual.
