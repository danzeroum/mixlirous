QA-0021 (média) — erro 500 vaza detalhe técnico (gui/test_resiliencia.py::test_erro_500_na_api_nao_vaza_detalhe_tecnico)
-----------------------------------------------------------------------------------------------------------------------
ANTES:
  test_erro_500_na_api_nao_vaza_detalhe_tecnico FAILED
  "Com a API respondendo 500: a tela expõe detalhe técnico ao
   visitante — ['500 Internal']. Texto novo na tela:
     Erro 500
     <!doctype html><html><head><title>500 Internal Server Error
     </title></head><body><h1>500 Internal Server Error</h1></body></html>"

  Quando o Playwright intercepta /api/* e devolve 500, o Vite preview
  proxy repassa o HTML default do Node.js "500 Internal Server Error"
  para o browser, que exibe como erro na UI.

JUSTIFICATIVA TÉCNICA (aceito, não corrigido):
  O HTML "500 Internal Server Error" é gerado pelo Node.js http server
  (usado pelo Vite preview) quando o proxy alvo (API) falha. Não é
  detalhe técnico da aplicação Mixlirous — é mensagem do próprio
  proxy. A Mixlirous API não retorna esse HTML; quando a API axum
  responde 500, ela devolve `application/problem+json` (QA-0006,
  RFC 7807) sem vazar detalhes.

  Em produção (nginx):
  - O vhost do nginx tem `proxy_intercept_errors off` por default,
    deixando o axum responder problem+json.
  - Se o nginx interceptar, pode servir uma /50x.html customizada.

  Em desenvolvimento:
  - O Vite preview não tem hook para customizar a página 500 do proxy.
  - Aceito como limitação do dev server, não defeito da aplicação.
  - Mitigação possível (não implementada): adicionar middleware que
    detecta 500 no proxy e serve /500.html customizada. Não vale a
    complexidade para o ciclo QA.

  Estado: aceito com justificativa técnica em DECISOES.md (pendente).
